# 담보물 배분표 결과 Excel 작성 지침서

## 0. 구현 원칙

Excel 작성 함수는 LLM이 만든 의미 계획 JSON을 받아 빈 워크북에서 결과를 생성한다.

```python
write_collateral_workbook(
    workbook_plan,
    output_path,
)
```

함수에 `template_path` 인자를 두지 않는다. 셀 좌표, 행 높이, 열 너비, 병합, 테두리, 수식은 작성 함수가 결정론적으로 처리한다.

LLM은 데이터 의미를 판단하고, Excel 함수는 그 판단 결과를 형식에 맞게 쓴다.

Excel 작성기는 주소 매칭, 오탈자 교정, O/X 판정을 다시 수행하지 않는다. 의미 계획에 없는 값을 GT 파일이나 이전 실행 결과에서 복사해서도 안 된다.

---

# 1. 작성 전 입력 검증

다음 조건을 만족하지 않으면 Excel 생성을 중단하거나 오류 보고서를 함께 반환한다.

1. `real_estate_tables`가 1개 이상 존재
2. 각 부동산 표의 `registry_ids`, `properties`, `mortgages`가 존재
3. 모든 금액은 정수 또는 `null`
4. 모든 날짜는 파싱 가능한 날짜
5. `machinery_table.quantity_total`이 기계기구 행 수량 합계와 일치
6. `machinery_table.total_appraised_value`가 기계기구 금액 합계와 일치
7. 대조표 각 행의 목록번호 키 집합이 머리글 목록번호 집합과 일치
8. 배분액·배분잔액은 모두 `null`
9. `status == "ok"`이고 `review_required`, `blocking_errors`가 모두 비어 있음
10. `unit_price: null`은 그대로 유지되며 역산값이 들어 있지 않음

정확도 우선 기본값은 fail-closed이다. 9번을 만족하지 않으면 최종 Excel을 생성하지 않는다. 사용자가 명시적으로 검토용 미완성본을 요청한 경우에만 미확정 셀을 공란으로 둔 별도 파일을 만들 수 있다.

# 2. 워크북 초기화

## 2.1 기본 설정

- 빈 워크북 생성
- 시트 1개 생성
- 기본 글꼴 `맑은 고딕`
- 확대 비율 61%
- 틀 고정 없음
- 명시적 테두리를 사용하므로 기본 격자선은 숨겨도 됨
- `A:P` 열 너비는 구조도 설명서의 고정값 적용
- 대조표가 P열을 넘어가면 추가된 모든 목록 열 너비를 20.14로 설정

## 2.2 데이터 형식

| 데이터 | Excel 저장형 |
| --- | --- |
| 날짜 | Excel 날짜형, 표시 `yyyy.mm.dd` 또는 GT와 같은 단기 날짜 형식 |
| 제작연월 | 원본이 연월뿐이면 문자열 `YYYY.MM` 또는 안전한 연월 표시값 |
| 금액 | 숫자형 정수, 표시 `#,##0` |
| 수량 | 숫자형 정수 |
| 목록번호 | 문자열 |
| `O`, `X` | 문자열 |
| 미확정·배분액·배분잔액 | 빈 셀 |

표시용 문자열과 원천 수치는 섞지 않는다. `maximum_claim`, `total_appraised_value`, `amount`, `quantity`, 숫자형 `unit_price`는 숫자 셀로 쓴다.

# 3. 행 커서 기반 동적 배치

고정 행 번호를 사용하지 말고 `current_row` 커서를 이동한다.

## 3.1 부동산 영역

```text
current_row = 1
채무자 행 작성
current_row += 1
부동산 제목 행 작성
current_row += 1

각 real_estate_table 반복:
    담보권자 행 1
    머리글 2
    본문 body_height
    각주 1
    다음 표가 있으면 빈 행 2
```

GT는 첫 표 본문이 6~14행, 둘째 표 본문이 21~29행이지만 이는 담보설정 6개인 현재 사례의 결과일 뿐이다.

## 3.2 기계기구 영역

마지막 부동산 표 각주 뒤에 빈 행 1개를 둔 후 다음 순서로 쓴다.

```text
채무자 행 1
기계기구 제목 행 1
빈 행 1
담보권자 행 1
머리글 2
본문 body_height
각주 2
빈 행 1
대조표
```

# 4. 공통 배분표 작성 함수

부동산과 기계기구 표는 하나의 공통 렌더 함수로 작성할 수 있다.

```python
write_distribution_table(
    sheet,
    start_row,
    collateral_location_text,
    collateral_detail_text,
    mortgages,
    appraised_value,
    note_text,
    is_machinery=False,
)
```

## 4.1 머리글 병합

시작 행을 `r`이라 할 때:

- `A{r}:A{r+1}`
- `B{r}:B{r+1}`
- `C{r}:F{r}`
- `G{r}:G{r+1}`
- `H{r}:O{r+1}`
- `P{r}:P{r+1}`

기계기구 여부에 따라 B 머리글의 `(주2)`만 다르게 쓴다.

## 4.2 본문 높이와 병합

```text
n = len(mortgages)
block_count = ceil(n / 2)
body_height = max(n, block_count * 3)
body_start = r + 2
body_end = body_start + body_height - 1
```

다음 범위를 각각 병합한다.

- `A{body_start}:A{body_end}`
- `B{body_start}:B{body_end}`
- `G{body_start}:G{body_end}`
- `P{body_start}:P{body_end}`

## 4.3 C:F 담보설정현황

정렬된 mortgage를 위에서부터 한 행씩 쓴다.

| 열 | 값 |
| --- | --- |
| C | 1부터 시작하는 순위 |
| D | `registration` |
| E | `mortgagee` |
| F | `공담` 또는 정규화 결과 |

담보설정 수보다 본문이 긴 경우 남은 C:F 행은 공란이다.

## 4.4 H:O 배분내역 블록

각 블록 `b = 0, 1, ...`에 대해:

```text
block_row = body_start + b * 3
left_mortgage_index = b * 2
right_mortgage_index = b * 2 + 1
```

왼쪽 담보권:

- `H:block_row : K:block_row` 병합 후 `{순위}순위`
- 다음 행 H:K에 `설정자`, `설정금액`, `배분액`, `배분잔액`
- 그다음 행 H에 채권자, I에 채권최고액, J·K는 공란

오른쪽 담보권:

- `L:block_row : O:block_row` 병합 후 `{순위}순위`
- 다음 행 L:O에 같은 소제목
- 그다음 행 L에 채권자, M에 채권최고액, N·O는 공란

배분액과 배분잔액은 계산식도 넣지 않는다.

# 5. 부동산 표 작성

## 5.1 부동산 제목과 담보권자

- 문서 맨 위 A열에 `채무자 : {borrower_name}`
- 다음 행 `A:P` 병합 후 `<부동산 담보물 배분표>`
- 각 그룹 시작 행 A에 `담보권자 : {mortgagee}`
- 같은 행 `O:P` 병합 후 `(단위:원)`

## 5.2 A열과 B열

`properties`를 `토지 → 건물 → 기타` 순으로 표시한다. 같은 유형 헤더는 한 번만 쓴다.

A열은 소재지 중심의 짧은 목록, B열은 번호·세부 내역·감정평가 구성의 긴 설명이다. 줄바꿈을 사용하되 원문의 지번, 면적, 구조를 바꾸지 않는다.

## 5.3 G열 가치평가액

G열에는 LLM 계획의 `total_appraised_value`를 숫자로 쓴다. Excel 작성 함수가 주소 문자열을 다시 매칭하거나 금액을 재판단하지 않는다.

단, 다음 산술 검증은 수행한다.

```text
total_appraised_value == sum(appraisal_matches[*].appraised_value)
```

불일치하면 생성을 중단한다.

## 5.4 완전한 GT 회귀 데이터 검증

- 첫 부동산 표: 5,681,855,200
- 둘째 부동산 표: 145,500,000
- 두 표 합계: 5,827,355,200

이 값은 테스트 assertion으로 사용할 수 있지만 일반 함수에 하드코딩하지 않는다.

# 6. 기계기구 배분표 작성

## 6.1 제목과 본문

- `A:P` 병합 후 `<기계기구 담보물 배분표>`
- A열에는 선택된 담보설정 그룹의 공장 소재지
- B열 첫 줄에는 `기계기구{quantity_total}식`
- 이어서 각 mortgage의 순위와 `mortgage_list_no`를 한 줄씩 표시
- 목록번호가 빈 mortgage는 목록번호 줄을 만들지 않음
- G열에는 `total_appraised_value`

## 6.2 완전한 GT 회귀 데이터 검증

```text
quantity_total = 10
total_appraised_value = 179,890,000
mortgage_list_no count = 6
```

기계기구 행이 9개여도 B열은 `기계기구10식`으로 쓴다.

## 6.3 각주

- 감정평가 기준일과 기관이 입력 메타데이터에 있으면 `(주1)`에 사용
- 메타데이터가 없으면 GT의 2025년 6월 27일과 기관명을 복사하지 않음
- `(주2) 담보설정된 기계기구내역은 다음과 같습니다.`는 구조 안내 문구로 사용 가능

# 7. 기계기구 대조표 작성

## 7.1 시작 범위

기계기구 `(주2)` 각주 다음 빈 행 뒤에서 즉시 머리글을 시작한다. 별도의 대조표 제목 행은 만들지 않는다.

## 7.2 열 생성

고정 열은 A:I이다.

| 열 | 머리글 | 작성값 |
| --- | --- | --- |
| A | `일변번호` | 1부터 연속 순번 |
| B | `명칭` | `name` |
| C:D | `제작자` | `manufacturer` |
| E:F | `제작일자` | `manufacture_date` |
| G | `수량` | `quantity` |
| H | `단가` | 표시 단가 |
| I | `금액` | `amount` |

`J`부터 `mortgage_list_numbers` 순서대로 열을 만든다. 목록번호 수가 6개라는 가정을 두지 않는다.

## 7.3 병합

- 머리글 C:D, E:F
- 각 본문 행 C:D, E:F
- 합계행 A:F
- 목록번호 열은 병합하지 않음

## 7.4 값 작성

- 본문 행 순서는 감정평가 JSON 순서 유지
- H열 단가는 LLM 계획의 검증 완료된 표시값 사용
- I열 금액은 원문 `amount`를 숫자로 사용
- 목록 셀은 확정 포함 `O`, 확정 미포함 `X`, 미확정은 공란
- 공란인 미확정 셀은 별도 오류 목록과 연결

`unit_price`가 `null`이면 H열은 공란이다. `amount / quantity` 계산식이나 역산 상수를 넣지 않는다. `unit_price`가 숫자인 행만 `unit_price * quantity == amount`를 다시 검증한다.

## 7.5 합계행

```text
G = SUM(본문 수량)
H = 공란
I = SUM(본문 금액)
각 목록 열 = 모든 본문 행이 O이면 O, 아니면 공란
```

현재 데이터의 합계는 G `10`, I `179,890,000`이어야 한다.

# 8. 서식 적용

## 8.1 공통 배분표

- 제목: 맑은 고딕 16pt, 굵게, 가운데
- 본문: 11pt
- 각주: 10pt
- 머리글: 10pt 굵게, 배경 `#B7DEE8`
- 본문 행 높이: 긴 표 50pt, 짧은 표 40pt
- 전체 표: 얇은 검정 실선
- A·B: 세로 가운데, 자동 줄바꿈
- C:F, H:O: 가로·세로 가운데
- 금액: 우측 정렬, `#,##0`

## 8.2 대조표

- 머리글 높이 56.5pt, 배경 `#D9D9D9`
- 본문 높이 24pt
- 합계 높이 17pt
- 글꼴 11pt
- 목록번호 머리글 자동 줄바꿈
- A·G 및 O/X는 가운데
- H·I 금액은 우측 정렬, `#,##0`
- 모든 셀 얇은 검정 실선

# 9. 저장 전 품질검사

## 9.1 데이터 검사

- 완전한 GT 회귀 입력에서는 등기부 4개가 표 2개로 생성됨
- 첫 그룹 registry가 `01·03·04`, 둘째가 `02`
- 순위가 날짜순이고 같은 날짜의 원본 순서가 보존됨
- 가치평가액 중복 합산 없음
- G열 값이 감정평가 매칭 합계와 일치
- 설정금액이 해당 순위의 `maximum_claim`과 일치
- J·K·N·O 배분액·잔액이 공란
- 기계기구 수량·금액 합계 일치
- 대조표 행 수가 감정평가 기계기구 항목 수와 일치
- 대조표 동적 열 수가 고유 목록번호 수와 일치
- `O`, `X`, 공란이 각각 포함, 미포함, 판단 불가의 의미로만 사용됨
- 원문 `unit_price: null` 행의 H열이 공란임
- manifest에 없는 registry가 생성되지 않음
- 새 6개 JSON만 입력한 실행에서 `registry_04`가 생성되지 않음
- 새 `registry_02` 주소 충돌이 해소되지 않았다면 `status != ok`로 최종 생성이 중단됨

## 9.2 Excel 검사

- 잘못된 병합 범위 없음
- 모든 동적 표가 앞 표와 겹치지 않음
- 제목은 영역별 한 번만 표시
- 숫자가 문자열로 저장되지 않음
- 날짜가 잘못된 일련번호로 표시되지 않음
- `#REF!`, `#VALUE!`, `#DIV/0!`, `#NAME?`, `#N/A` 없음
- 렌더링 후 긴 주소·목록번호·B열 설명이 잘리지 않음
- 대조표가 P열을 넘어가도 모든 추가 열에 너비와 테두리가 적용됨

## 9.3 완료 조건

완성 함수는 JSON 입력과 출력 경로만으로 실행되어야 하며, GT 또는 예시 Excel 파일이 없어도 동일한 구조의 결과를 생성해야 한다.

완성 후에는 의미 계획 JSON과 Excel 셀의 핵심 값을 역대조한다. 최소한 각 부동산 표의 `registry_ids`, G열 가치평가액, C:F 담보설정현황, H:O 설정금액, 기계기구 수량·금액 합계, 모든 목록별 O/X를 확인해야 한다.
