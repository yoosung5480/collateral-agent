# 담보물 배분표 Excel 구조도 설명서

## 0. 문서 목적

이 문서는 `담보물배분표GT.xlsx`를 **한 번 분석한 결과를 코드 규칙으로 고정**하기 위한 구조 명세이다. 실제 운영 함수는 템플릿 Excel을 다시 입력받지 않는다. 빈 워크북을 만든 뒤 JSON 데이터의 개수에 맞춰 행과 열을 동적으로 생성해야 한다.

이 문서는 셀의 배치와 반복 구조만 정의한다. 문서 간 의미 대조는 `02_JSON에서_엑셀생성_LLM_지침서.md`, 실제 셀 생성은 `03_결과_엑셀_작성_지침서.md`의 책임이다.

현재 GT 파일은 구조를 설명하기 위한 한 사례이다. 다음 값은 고정값이 아니다.

- 부동산 표 2개
- 담보설정 6개
- 기계기구 9행, 수량 합계 10
- 저당목록 6개
- 현재 사례의 행 번호와 금액

## 0.1 데이터 원천의 우선순위

| 값 | 유일한 원천 | 금지 사항 |
| --- | --- | --- |
| 부동산 자체 정보 | 등기부 `title.json` | 감정평가서의 표현으로 표제부를 덮어쓰기 |
| 담보설정현황·설정금액·목록번호 | 등기부 `encumbrance.json` | 가치평가액을 설정금액으로 사용 |
| 부동산 가치평가액 | 토지·건물 감정평가 JSON | 등기부 금액 또는 비율로 추정 |
| 기계기구 기준 행·수량·가치평가액 | 기계기구 감정평가 JSON | 저당목록 행을 기준 행으로 사용 |
| 목록별 기계기구 포함 여부 | 저당목록 JSON과 감정평가 JSON의 대조 결과 | 명칭만으로 `O` 판정 |
| 배분액·배분잔액 | 원천 없음 | 어떠한 산식으로도 생성 |

표시값과 비교값은 구분한다. 주소·명칭의 정규화 문자열은 매칭에만 사용하고 Excel에는 원문 또는 승인된 표시 문자열을 쓴다.

# 1. Excel 전체 구조

## 1.1 워크북 단위

| 항목 | 규칙 |
| --- | --- |
| 시트 수 | 기본 1개 |
| 시트명 | `Sheet1` 또는 프로젝트 지정값 |
| 기본 글꼴 | 맑은 고딕 |
| 표시 배율 | GT 기준 61% |
| 틀 고정 | 없음 |
| 부동산·기계기구 배분표 폭 | 고정 `A:P` |
| 기계기구 대조표 폭 | 기본 `A:I` + 저당목록 수만큼 동적 열 |
| 템플릿 입력 | 금지. 빈 워크북에서 생성 |

실행 입력은 파일명이 아니라 명시적인 JSON manifest여야 한다. `title(6).json` 같은 업로드 파일명은 식별자로 사용하지 않고, JSON 내부 `registry_id`에서 `registry_XX`를 추출한다.

## 1.2 세로 배치 순서

워크북은 위에서 아래로 다음 네 영역을 갖는다.

1. 채무자 행과 `<부동산 담보물 배분표>` 제목
2. 담보설정현황 그룹 수만큼 반복되는 부동산 담보물 배분표
3. 채무자 행과 `<기계기구 담보물 배분표>` 제목 및 기계기구 담보물 배분표
4. 기계기구 담보물 배분표 대조표

부동산 등기부 개수와 부동산 표 개수는 같지 않다. 동일한 담보설정현황을 공유하는 등기부들은 한 표에 합친다.

## 1.3 고정 열 너비

GT에서 확인된 `A:P` 열 너비는 다음과 같다.

| 열 | 너비 | 주 용도 |
| --- | ---: | --- |
| A | 17.14 | 담보물 소재지 |
| B | 45.00 | 담보물 내역 |
| C | 4.14 | 순위 |
| D | 15.57 | 설정일자 |
| E | 16.14 | 채권자 |
| F | 5.57 | 공담 |
| G | 20.14 | 가치평가액 |
| H:O | 각 20.14 | 배분내역 또는 대조표 금액·목록 열 |
| P | 14.14 | 비고 |

> 기존 명세의 `I:O = 13.00`은 GT와 다르다. 실제 GT에서는 `H:O`가 모두 약 20.14이다.

## 1.4 공통 배분표 머리글

부동산 표와 기계기구 표는 동일한 2행 머리글을 사용한다.

| 병합 범위 | 첫째 행 | 둘째 행 |
| --- | --- | --- |
| A열 2행 세로 병합 | `담보물 소재지` | - |
| B열 2행 세로 병합 | `담보물 내역 (담보물의 면적 및 수량)` | - |
| C:F 첫째 행 병합 | `담보설정현황` | C `순위`, D `설정일자`, E `채권자`, F `공담` |
| G열 2행 세로 병합 | `가치평가액 (주1)` | - |
| H:O 두 행 전체 병합 | `배분내역` | - |
| P열 2행 세로 병합 | `비고` | - |

기계기구 표의 B열 머리글만 다음처럼 `(주2)`를 추가한다.

```text
담보물 내역
(담보물의 면적 및 수량)(주2)
```

머리글 서식은 맑은 고딕 10pt 굵게, 배경 `#B7DEE8`, 가로·세로 가운데, 줄바꿈, 얇은 검정 실선 테두리이다. 두 머리글 행 높이는 각각 21pt이다.

## 1.5 담보설정 본문 높이

담보설정 수를 `n`이라 하면 오른쪽 배분내역은 담보권 2개를 3행 한 블록으로 표현한다.

```text
block_count = ceil(n / 2)
body_height = max(n, block_count * 3)
```

현재처럼 `n = 6`이면 본문은 9행이다.

본문 전체에서 A, B, G, P열은 각각 세로 병합한다. C:F는 담보설정 1개당 한 행을 사용하고, `n`개 입력 후 남는 행은 공란이다.

배분 블록은 다음과 같다.

| 블록 상대행 | H:K | L:O |
| ---: | --- | --- |
| 1 | 홀수 순위 제목 병합 | 짝수 순위 제목 병합 |
| 2 | `설정자`, `설정금액`, `배분액`, `배분잔액` | 동일 |
| 3 | 채권자, 채권최고액, 공란, 공란 | 채권자, 채권최고액, 공란, 공란 |

담보권 수가 홀수이면 마지막 블록의 L:O는 공란이다.

# 2. 부동산 담보물 배분표

## 2.1 표 생성 단위

표 생성 단위는 등기부가 아니라 **동일 담보설정현황 그룹**이다.

현재 GT의 기대 그룹은 다음과 같다.

| 표 | 포함 등기부 | 담보물 |
| --- | --- | --- |
| 부동산 표 1 | `registry_01`, `registry_03`, `registry_04` | 토지 1건 + 건물 2건 |
| 부동산 표 2 | `registry_02` | 토지 1건 |

즉, 입력 등기부는 4개이지만 출력 표는 2개이다.

현재 새로 제공된 6개 파일은 `registry_01`, `registry_02`, `registry_03`의 **3개 등기부 형식 표본**이다. 이 6개만 실행 입력으로 사용하면 `registry_04`를 만들어서는 안 되며, 담보설정현황 그룹은 `{registry_01, registry_03}`과 `{registry_02}`가 된다. 위의 4개→2개 결과는 `registry_04`까지 포함된 완전한 GT 회귀 데이터에 대한 기대값이다.

## 2.2 영역 배치

첫 부동산 표 앞에서만 다음 두 행을 만든다.

1. `채무자 : {borrower_name}`
2. `A:P` 병합 후 `<부동산 담보물 배분표>`

각 부동산 그룹은 다음 순서로 작성한다.

1. `담보권자 : {mortgagee}` 및 우측 `(단위:원)`
2. 공통 2행 머리글
3. 동적 본문
4. 가치평가 기준 각주
5. 다음 그룹이 있으면 빈 행을 두고 다음 표 작성

두 번째 표부터는 채무자와 `<부동산 담보물 배분표>` 제목을 반복하지 않는다.

## 2.3 본문 열 의미

| 열 | 표시 내용 | 데이터 원천 |
| --- | --- | --- |
| A | `<토지>`, `<건물>`별 소재지 목록 | `title.json` |
| B | 종류별 번호, 소재지, 면적·구조, 가치평가 세부 설명 | `title.json` + 감정평가 JSON |
| C | 날짜순 출력 순번 | `encumbrance.json`에서 계산 |
| D | 설정일자 | `registration` |
| E | 채권자 | `mortgagee` |
| F | `공담` | `shared_collateral` 정규화 |
| G | 해당 부동산 그룹의 가치평가액 합계 | 토지·건물 감정평가 JSON |
| H:O | 순위별 설정자·설정금액·배분액·배분잔액 | 을구 JSON + 공란 규칙 |
| P | 비고 | 근거 데이터가 있을 때만 사용 |

## 2.4 A·B열 표시 구조

A열은 부동산 유형과 대표 소재지를 읽기 쉽게 나열한다.

```text
<토지>
소재지 1

<건물>
소재지 2
소재지 3
```

B열은 유형별로 번호를 다시 시작하고, `title.json`의 원문 의미를 보존한다.

```text
<토지>
1. 소재지
- 지목 및 면적

<건물>
1. 소재지
- 구조 및 층별 면적

2. 소재지
- 구조 및 층별 면적

<가치평가액>
토지: ...원
건물: ...원
제시외건물: ...원
```

가치평가 설명과 G열 금액은 반드시 감정평가 JSON을 대조한 결과여야 한다. 단순 문자열 포함 규칙으로 자동 연결하면 안 된다.

## 2.5 완전한 GT 회귀 데이터 검산값

`registry_04`까지 포함된 완전한 GT 회귀 입력에서는 다음 값이 나와야 한다.

| 표 | 가치평가액 |
| --- | ---: |
| `registry_01·03·04` 그룹 | 5,681,855,200원 |
| `registry_02` 그룹 | 145,500,000원 |
| 합계 | 5,827,355,200원 |

이는 현재 데이터의 검산값일 뿐 코드 상수가 아니다.

# 3. 기계기구 담보물 배분표

## 3.1 표 생성 단위

기계기구 표는 저당법 목록번호가 연결된 담보설정현황 그룹 하나를 기준으로 생성한다. 현재 GT에서는 `registry_01·03·04` 그룹의 6개 담보설정을 사용한다.

## 3.2 영역 배치

부동산 영역 다음에 다음 순서로 배치한다.

1. `채무자 : {borrower_name}`
2. `A:P` 병합 후 `<기계기구 담보물 배분표>`
3. 빈 행
4. `담보권자 : {mortgagee}`
5. 공통 2행 머리글
6. 동적 본문
7. `(주1)` 가치평가 기준 각주
8. `(주2)` 저당목록 안내 각주

## 3.3 본문 열 의미

| 열 | 표시 내용 | 데이터 원천 |
| --- | --- | --- |
| A | 기계기구가 설치된 담보 소재지 | 선택된 등기부 그룹의 `title.json` |
| B | `기계기구{수량합계}식`과 순위별 저당법 목록번호 | 기계기구 감정평가 JSON + 을구 JSON |
| C:F | 순위, 설정일자, 채권자, 공담 | 을구 JSON |
| G | 기계기구 가치평가액 합계 | 기계기구 감정평가 JSON의 `amount` 합계 |
| H:O | 순위별 설정자, 설정금액, 공란 배분액·배분잔액 | 을구 JSON |
| P | 비고 | 근거가 있을 때만 사용 |

B열 표시 예시는 다음과 같다.

```text
기계기구10식
1순위: 공장 및 광업재단 저당법 제6조 목록 제2012-399호
2순위: 공장 및 광업재단 저당법 제6조 목록 제2012-514호
...
```

`10식`의 10은 감정평가 행 수가 아니라 `quantity` 합계이다. 현재 GT의 감정가액은 `amount` 합계인 179,890,000원이다.

# 4. 기계기구 담보물 배분표 대조표

## 4.1 기본 구조

대조표는 감정평가서의 기계기구 항목을 행 기준으로 삼고, 저당법 목록을 열 기준으로 삼는다.

```text
행 수 = 머리글 1행 + 감정평가 기계기구 항목 수 k + 합계 1행
열 수 = 고정 9열(A:I) + 고유 저당법 목록 수 m
마지막 열 = I에서 오른쪽으로 m개 이동한 열
```

현재 GT에서는 `k = 9`, `m = 6`이므로 표 범위는 `A50:O60`이다. 실제 시작 행과 마지막 열은 앞 영역 크기에 따라 달라져야 한다.

## 4.2 고정 열 A:I

| 열 | 병합 | GT 머리글 | 값 원천 |
| --- | --- | --- | --- |
| A | 없음 | `일변번호` | 출력 순번 1부터 시작 |
| B | 없음 | `명칭` | 감정평가 `name` |
| C:D | 행별 병합 | `제작자` | `manufacturer` |
| E:F | 행별 병합 | `제작일자` | `manufacture_date` |
| G | 없음 | `수량` | `quantity` |
| H | 없음 | `단가` | 감정평가 JSON의 숫자형 `unit_price` |
| I | 없음 | `금액` | `amount` |

GT 원문 머리글은 오탈자로 보이는 `일변번호`이다. 회계사 양식을 그대로 재현할 때는 이를 유지한다. 문구 교정 요구가 별도로 있으면 `일련번호`로 바꾼다.

H열은 `unit_price`가 숫자로 제공된 경우에만 채운다. 현재 감정평가 JSON에서 `unit_price: null`은 원문 단가가 `-`였다는 뜻이므로 `amount / quantity`로 역산해 채우지 않는다. GT에 단가가 표시되어 있더라도 현재 JSON만으로 재생성하는 실행에서는 출처 없는 값을 복사하지 않는다.

## 4.3 동적 저당목록 열

`J`열부터 고유 `mortgage_list_no`를 담보설정 순서대로 하나씩 만든다. 현재 예시는 다음 6개라서 `J:O`를 사용한다.

1. 제2012-399호
2. 제2012-514호
3. 제2012-515호
4. 제2012-720호
5. 제2017-309호
6. 제2018-234호

머리글에는 축약번호가 아니라 `공장 및 광업재단 저당법 제6조 목록 제YYYY-NNN호` 전체 문구를 쓴다.

## 4.4 본문과 합계행

- 기계기구 감정평가 항목 1개당 본문 1행을 만든다.
- 머리글과 모든 본문 행에서 C:D, E:F를 각각 가로 병합한다.
- 목록별 본문 셀은 최신 업무 규칙에 따라 포함 `O`, 미포함 `X`를 쓴다.
- 감정평가서와 저당목록 대조가 모호하면 임의로 `O`나 `X`를 쓰지 않고 공란과 검토 오류를 남긴다.
- 마지막 합계행은 A:F를 병합해 `계`, G에 수량 합계, H는 공란, I에 금액 합계를 쓴다.
- 합계행의 목록 열은 해당 목록이 모든 기계기구를 포함하면 `O`, 그렇지 않으면 GT처럼 공란으로 둔다.

GT 원본은 미포함 셀이 공란이지만, 최신 업무 규칙은 `X`를 요구한다. 따라서 본문은 `O/X/공란`의 3상태를 사용한다. 여기서 공란은 미포함이 아니라 **판단 불가**이다.

# 5. 공란으로 유지해야 하는 값

| 항목 | 처리 |
| --- | --- |
| 배분액 | 원천 데이터가 없으므로 공란 |
| 배분잔액 | 원천 데이터가 없으므로 공란 |
| 비고 | 근거 데이터가 없으면 공란 |
| 감정평가 기관·기준일 | 입력 메타데이터에 없으면 GT 문구를 복사하지 않음 |
| 모호한 저당목록 대조 | 공란 + 검토 오류 |

부동산 가치평가액이나 기계기구 포함 여부처럼 결과를 바꾸는 핵심 셀이 모호하면 기본 동작은 최종본 생성을 중단하는 것이다. 검토용 미완성본을 별도로 허용한 경우에만 해당 셀을 공란으로 둔다.

배분액을 채권최고액, 가치평가액 또는 비율로 계산해서는 안 된다.

# 6. Excel 접근 도구가 제공해야 하는 기능

Agent에게 제공하는 Excel tool은 개별 셀을 임의 편집하는 범용 도구보다 다음 고수준 동작을 명시적으로 지원하는 편이 안전하다.

| 동작 | 필수 입력 | 검증 |
| --- | --- | --- |
| 워크북 초기화 | 시트명, 기본 글꼴, 확대 비율 | 시트 1개 생성 확인 |
| 열 구조 설정 | `A:P` 고정 너비, 대조표 동적 목록 열 | 마지막 열 계산 확인 |
| 배분표 작성 | 시작 행, mortgages, A/B 표시문, 가치평가액 | 본문 높이·병합 충돌 확인 |
| 대조표 작성 | 감정평가 기준 행, 목록번호 배열, O/X/null 행렬 | 행·열 크기 일치 확인 |
| 수식·숫자 형식 적용 | 합계 범위, 날짜·금액 형식 | 수식 오류와 문자열 금액 검사 |
| 렌더·저장 | 출력 경로 | 전체 영역 시각 검증 후 저장 |

권장되는 최상위 호출 단위는 다음과 같다.

```text
write_collateral_workbook(workbook_plan, output_path)
```

`workbook_plan`은 02 문서가 정의한 의미 계획이며, tool 내부에서는 LLM을 다시 호출하지 않는다. tool은 결정론적으로 행 커서, 병합, 서식, 수식만 처리한다.
