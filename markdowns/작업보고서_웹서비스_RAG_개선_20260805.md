# 웹서비스 및 RAG 개선 작업보고서

## 1. 작업 목표

`README.md` 요구사항에 맞춰 담보물배분표 웹서비스를 재구성했다.

- 문서 형식 검사 3종을 병렬 실행하도록 변경
- 실패 작업도 경과시간, 토큰, 비용 추정치를 개발자 대시보드에 표시
- 유저 대시보드와 개발자 대시보드 분리
- `rag_chat` 독립 패키지 신설
- `workbook_plan.json` 기반 첫 보고서와 LangGraph/LangChain 채팅 히스토리 기반 RAG 채팅 구현
- 프레임워크 기존 API는 수정하지 않고 웹서비스 연동부에서만 최소 조정

## 3. 서버 API 구성

## 4. 웹서버와 파이썬 프레임워크 간 데이터 흐름

### 업로드 요청 JSON

브라우저는 `/api/jobs`로 다음 구조를 보낸다.

```json
{
  "registry": {
    "filename": "부동산등기부등본.pdf",
    "contentBase64": "..."
  },
  "appraisal": {
    "filename": "감정평가서.pdf",
    "contentBase64": "..."
  },
  "mortgageList": {
    "filename": "공장저당목록.pdf",
    "contentBase64": "..."
  }
}
```

서버는 Base64를 PDF 바이트로 저장한 뒤 기존 프레임워크의 parser/pipeline 함수에 업로드 파일 경로를 전달한다.

### 작업 상태 응답 JSON

`GET /api/jobs/{job_id}`는 유저 UI에 필요한 상태만 반환한다.

```json
{
  "jobId": "내부 식별자",
  "status": "running",
  "progress": 41,
  "requestTime": "2026-08-05 14:21:33",
  "inputFiles": {
    "registry": "부동산등기부등본.pdf",
    "appraisal": "감정평가서.pdf",
    "mortgage_list": "공장저당목록.pdf"
  },
  "elapsedSeconds": 73.2,
  "steps": [],
  "downloadUrl": null
}
```

유저 화면과 유저 대시보드는 `jobId`를 핵심 표시값으로 쓰지 않고, 업로드 파일명과 초단위 요청시간을 기준으로 보여준다.

## 5. 저장 위치

작업별 실행 루트는 다음과 같다.

```text
web_service/runtime/jobs/{job_id}/
```

| 구분 | 저장 경로 |
| --- | --- |
| 유저 업로드 PDF | `web_service/runtime/jobs/{job_id}/uploads/` |
| 기존 프레임워크 parser 산출물 | `web_service/runtime/jobs/{job_id}/framework_output/` |
| 파이프라인 중간 JSON 산출물 | `web_service/runtime/jobs/{job_id}/pipeline_artifacts/` |
| 최종 workbook plan | `web_service/runtime/jobs/{job_id}/pipeline_artifacts/05_excel/workbook_plan.json` |
| 최종 Excel | `web_service/runtime/jobs/{job_id}/final/담보물배분표.xlsx` |
| 프레임워크 LLM 비용 요약 | `web_service/runtime/jobs/{job_id}/pipeline_artifacts/99_cost_tracking/{run_session_id}/cost_summary.json` |
| 비용 JSONL ledger | `web_service/runtime/jobs/{job_id}/cost_tracking_data/` |
| RAG 인덱스 | `web_service/runtime/jobs/{job_id}/rag/rag_index.json` |
| RAG 첫 보고서 | `web_service/runtime/jobs/{job_id}/rag/initial_report.md` |
| RAG 임베딩 사용량 | `web_service/runtime/jobs/{job_id}/rag/rag_usage_summary.json` |
| RAG LLM 비용 요약 | `web_service/runtime/jobs/{job_id}/rag/cost_tracking/cost_summary.json` |

## 6. 병렬 문서 형식 검사

기존 순차 실행 구조를 `validate_inputs_async()`로 분리했다.

- `is_registry()`
- `is_appraisal()`
- `is_mortgaga_list()`

세 검사는 `asyncio.gather(..., return_exceptions=True)`와 `asyncio.to_thread()`로 동시에 실행된다. 한 검사가 실패해도 나머지 검사가 끝날 때까지 기다린 뒤 실패 보고서를 저장하고 작업을 실패 상태로 전환한다. 따라서 실패한 작업도 완료된 검증 호출의 토큰/비용이 개발자 대시보드에 반영된다.

## 7. RAG 패키지 설계

새 패키지 `rag_chat`는 웹서버와 분리되어 독립적으로 사용할 수 있게 구성했다.

핵심 클래스:

```python
from rag_chat import RagChatManager
```

주요 책임:

1. `pipeline_artifacts/**/*.json` 탐색
2. JSON 원문을 그대로 임베딩하지 않고 규칙 기반 텍스트로 변환
3. `workbook_plan.json`을 특별 처리해 핵심 요약 생성
4. 요약/행 단위 텍스트 청킹 후 임베딩 저장
5. `create_agent()` + `InMemorySaver()` + 전역 `DEFAULT_THREAD_ID`로 같은 세션 대화 히스토리 유지
6. 모든 답변의 시스템 프롬프트에 가공된 `workbook_plan.json` 요약을 항상 포함

RAG 첫 보고서는 `/api/jobs/{job_id}/rag/build` 호출 시 `workbook_plan.json` 요약을 기반으로 작성된다. 이후 사용자의 질문은 자동으로 RAG 검색을 수행하고 관련 중간산출물 출처를 답변에 포함한다.

## 8. 대시보드 분리

### 유저용 대시보드

메인 랜딩 페이지 하단에 유지했다.

- 전체 작업 수
- 완료 수
- 진행 중 수
- 실패 수
- 요청시간
- 업로드 파일명
- 상태/진행률/현재 단계
- Excel 다운로드 링크

토큰과 비용은 표시하지 않는다.

### 개발자용 대시보드

`/developer`에 별도 페이지를 추가했다.

- 프레임워크 LLM 호출 수/토큰/비용
- RAG 보고서·채팅 LLM 호출 수/토큰/비용
- RAG 임베딩 호출 수/토큰/비용
- 실패 작업의 경과시간과 실패 메시지
- 주요 산출물 저장 경로

## 10. 추가 수정 기록: initial_report UI 노출 및 RAG 소스 확장

추가 요구사항 반영 내용:

1. `initial_report.md`는 개발자 내부 산출물이 아니라 유저가 읽는 결과 리포트로 처리한다.
   - 자동화 성공 흐름에 `report` 단계를 추가했다.
   - 최종 Excel 생성 후 완료 상태로 전환하기 전에 `rag/initial_report.md`를 생성한다.
   - `GET /api/jobs/{job_id}` 응답에 `initialReport`, `initialReportPath`를 포함한다.
   - 웹 UI는 작업 완료 시 `initialReport`를 `실행내용 기반 리포트` 카드와 첫 assistant 메시지로 즉시 표시한다.

2. RAG 소스 데이터에 framework parser 원본성 JSON을 포함한다.
   - 기존: `{job_id}/pipeline_artifacts/**/*.json`
   - 변경: `{job_id}/pipeline_artifacts/**/*.json` + `{job_id}/framework_output/**/*.json`
   - `rag_chat.RagChatManager`에 `framework_output_dir` 인자를 추가했다.
   - `json_artifact_paths()`는 여러 root를 받아 중복 없이 JSON 파일을 수집한다.

추가 검증:

```text
python -m py_compile web_service/server.py rag_chat/manager.py '담보물배분표 _ver2/pipeline.py' '담보물배분표 _ver2/excel.py'
node --check web_service/static/app.js
node --check web_service/static/developer.js
RAG JSON root 검증: pipeline_artifacts/workbook_plan.json + framework_output/raw.json 동시 수집 확인
serialize_job 검증: initialReport, initialReportPath 응답 포함 확인
FastAPI TestClient: /, /developer, /api/health, /api/dashboard, /api/developer/dashboard = 200
```

## 11. 추가 수정 기록: Markdown 렌더링 및 대형 리포트 섹션 분리

추가 요구사항 반영 내용:

1. RAG agent 답변 Markdown 렌더링
   - `web_service/static/app.js`에 안전한 클라이언트 Markdown 렌더러를 추가했다.
   - assistant 답변과 첫 결과 보고서를 plain text가 아니라 HTML로 렌더링한다.
   - 지원 형식: 제목, 문단, 순서/비순서 목록, 굵게, 기울임, inline code, code block, blockquote, 구분선.
   - 렌더링 전 HTML escape를 적용해 임의 HTML 주입을 막는다.

2. `실행내용 기반 리포트` 독립 대형 섹션 분리
   - 기존에는 오른쪽 채팅 패널 내부에 리포트 카드가 있었다.
   - 이제 `workspace` 아래에 `section#report.report-wide.panel`로 분리했다.
   - 전체 가로 폭을 사용하는 큰 리포트 카드(`report-card-large`)로 표시한다.
   - 오른쪽 영역은 `산출물 기반 질의응답` 채팅 전용 패널로 정리했다.

추가 검증:

python -m py_compile web_service/server.py rag_chat/manager.py
